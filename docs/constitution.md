# Constitución — Torreta de Seguimiento Facial con Láser

Principios innegociables. Toda spec, plan y tarea debe cumplirlos.

1. **[Principio 1: Simplicidad y Stack]:** Stack fijo: firmware C++ sobre ESP32 ESP-WROOM-32 conectado por USB; visión y UI web local en Python 3 sobre el PC. El repo no declara hoy versiones, framework de firmware ni librerías: ninguna se instala hasta que el `plan.md` de la spec correspondiente la fije con versión exacta y se registre en `docs/memory/decisions.md`. Reglas: biblioteca estándar antes que dependencia externa; cada dependencia exige ADR con justificación y pin exacto; entorno aislado (venv) por componente Python; herramientas de test obligatorias y fijadas por ADR antes del primer test (pytest para Python; runner nativo del framework de firmware elegido). Prohibidos: paquetes globales, servicios en la nube, telemetría y APIs de pago.

2. **[Principio 2: Gobernanza de Especificaciones]:** La especificación manda. Ningún comportamiento se implementa sin estar definido explícitamente en una spec aprobada, con criterios verificables AC-1, AC-2… Si falta una decisión, el desarrollo se detiene y se consulta en un solo lote; no se elige en silencio. Si la realidad contradice la spec, se actualiza primero la spec. Toda excepción a esta constitución se justifica en el plan o se enmienda por ADR en `docs/memory/decisions.md`.

3. **[Principio 3: Arquitectura y Desacoplamiento]:** El core es lógica pura sin I/O: geometría, mapeo píxel→ángulo y decisión de centrado; se testea sin cámara, serial, red ni UI. Las interfaces son adaptadores finos: captura de cámara, puerto serial y servidor HTTP local. En el firmware, el control de movimiento y láser se separa del framing USB. Dependencia unidireccional: UI/visión → core → contrato serial → firmware; la UI no habla con el ESP32 y el core no habla con la cámara. Pines, índice de cámara, límites de servo y estado del láser viven en un único punto de configuración por componente.

4. **[Principio 4: Calidad y Testing]:** Condición de entrega: cada tarea finaliza obligatoriamente con sus pruebas en verde; prohibido avanzar o integrar con tests fallidos o no ejecutados. Cobertura 100% de ramas en el core puro; protocolo PC↔ESP32 validado contra un stub de puerto serial; cámara, servos y láser validados con checklist de banco reproducible y resultado registrado. Tests deterministas: sin esperas arbitrarias ni dependencia de red; tiempo y aleatoriedad inyectados. Una tarea sin verificación registrada no está terminada.

5. **[Principio 5: Persistencia y Datos]:** Sin base de datos ni llamadas de red externas. Foto de referencia y frames viven en memoria del proceso de visión; cualquier persistencia es opcional, en archivos locales dentro del directorio de trabajo y con ruta configurable. Nada sale de la LAN local ni se envía a terceros; no se almacenan imágenes de personas sin decisión explícita en una spec. Ángulos y estado del láser son efímeros y su autoridad reside en el firmware.

6. **[Principio 6: Convenciones de Idioma]:** Código, identificadores, nombres de archivos, ramas y mensajes de commit en inglés. UI, mensajes al usuario, documentación, specs, ADR y comentarios de código en español. Fechas en ISO-8601. Vocabulario del dominio según `docs/memory/glossary.md`.
